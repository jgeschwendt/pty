pty · docs

embeddable PTY sessions for Elixir hosts

erlexec drives one OS child per session, out of process; a session owns its PTY and outlives every client. Closing a tab, refreshing or dropping the network only detaches; reattaching by id replays the scrollback and rejoins the same live process, and any number of clients can share one terminal. The library serves nothing itself: the host owns the endpoint, the auth and the page.

Invariants

What every change must keep true.

  • a session outlives every client — only the child exiting or a reap ends it.
  • every end reaches subscribers as one {:pty_exit, code} — 129 for a reap or crash — except an untrappable kill, which skips terminate/2; Pty.Socket monitors the session for that. A local subscriber over :max_lag messages behind gets one {:pty_lagged} in place of further output, the live feed and a reap's relay alike, and is taken off the feed — yet still monitored, counted, and sent the one {:pty_exit, code}. A reap SIGHUPs, relays the child's last output, and after 2 s lets erlexec stop it (SIGTERM, then SIGKILL 1 s on, to the process group). A session's death, however abrupt, takes its child through the erlexec link.
  • reaps never go through the supervisor — GenServer.stop, so a slow hangup never blocks start/2; reap_all/0 hangs up concurrently. A reap frees its id before the hangup, so a start/2 meanwhile gets a fresh session, never the dying one, while a second reap/1 by id reaps that fresh one if there is one, else finds the dying one and returns once it is gone.
  • start/2 is idempotent and fail-closed on a missing binary or cwd, resolved as the child would (:cwd, :env PATH) — in the caller, outside the one supervisor every start shares, so a hung mount stalls only its own start.
  • a bad client frame is :ignore, never a crashed session.
  • the first server frame is the scrollback, even empty — the attach signal. pty.js resets its backoff only then, and every reconnect after the first attach is ?reattach, attach-only; a retry before it may still spawn.
  • idleness never closes a terminal, silence does — a terminal is idle whenever its human is thinking, so Pty.Socket pings every :ping_interval (30 s) and the browser's automatic pongs reset Pty.Plug's idle :timeout (90 s, kept above the interval). A client gone half-open stops answering and is closed, so its subscription never pins a session.
  • a cross-origin browser upgrade is refused unless :check_origin admits it.

Close codes

The client sends JSON text frames ({"t":"i","d":…} input, {"t":"b","d":…} raw bytes, one per code point 0–255, {"t":"r","cols":C,"rows":R} resize); the server sends raw output as binary frames, the scrollback first. Three private close codes are final, and pty.js stops on exactly those.

codemeaningpty.js
4000the session ended — its child exited or it was reapedstop · onExit
4404a reattach found no session, or the one found ended as it attachedstop · onExit
4422an invalid id, reattaching or not, or a refused spawn — :command or :cwd not found, or an option rejected, such as a bad :cols or a :max_lag that is no positive integer; permanentstop · onExit
1011any other start failure — pty cannot tell a passing failure (resources) from a fault (a malformed option); the host's logs show whichreconnect
1013a subscriber fell more than :max_lag messages behind and was taken off the feedreconnect · reattach, resync from scrollback
1000never the session's: Bandit sends it on its own shutdownreconnect
othertransport loss, or an upgrade Pty.Plug refused (400 bad id, 403 origin) — backed off, since the backoff resets only on attachreconnect, 1 s → 15 s

Hazards

Traps a change can walk into.

  • the shift sandbox — mise trust the worktree, copy deps/ from main, compile with MIX_OS_CONCURRENCY_LOCK=0, and run the suite as exactly shift-test mise x -C . -- mix test --cover (its profile allows /dev/ptmx; anything spliced in between breaks the exclusion). Its -C must sit under ~/.grove/code and its --log under that tree (the ignored tmp/), so a probe copy is a sibling of the worktree, never under ~/.sandman.
  • erlexec reports status 0 for any child it was asked to stop, racing the signal's own status — hence the fixed 129 for a reap.
  • exec-port's SIGHUP handler survives in a fork until execve — a reap within a child's first milliseconds misses the hangup and waits out the 2 s grace. Tests clean up with drop/1 (an outright kill) for that reason. The hangup is deliberately not re-sent: a second HUP may cut short a child's own cleanup.
  • erlexec runs a {:kill, cmd} under the BEAM's $SHELL -c, so a kill command is non-portable (nushell); the hangup is sent by :exec.kill/2.
  • Origin is compared with Host, so DNS rebinding is outside the check.
  • Input is unbounded — exec-port queues browser input without limit. Output is bounded per local subscriber: one more than :max_lag (1 000) messages behind gets a single {:pty_lagged} and is taken off the feed (the tmux resync model), where unbounded it grew the host VM by the child's whole output (64 MB in 2.5 s with zero reads). The hangup's relay is bounded the same way, and a lagged subscriber still hears the {:pty_exit, code}. A subscriber on another node is not measured: Process.info/2 is local-only.
  • An outright kill reaches only the child's process group — a job an interactive shell put in its own group (sleep 100000 &) outlives a :kill or a brutal supervisor kill; a reap's hangup reaches it through the shell.
